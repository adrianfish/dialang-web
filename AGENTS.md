## Project Overview

A Deno/Hono implementation of a language testing web application, DIALANG. All the backend code is
hosted under `src` and the client side code is hosted under `static`. All backend code is written
in TypeScript and client side JS is written in JavaScript.

## Tech Stack

- **Runtime:** Deno
- **Database:** Deno KV
- **Framework:** Hono, JQuery
- **Languages:** TypeScript and JavaScript

## Commands

```bash
# Run unit tests
deno task test

# Run end to end tests
deno task e2e

# Type-check
deno check

# Format code
deno fmt

# Lint code
deno lint

# Run end to end tests
deno task e2e
```

## Project Structure

```
.
├── main.ts               # App entry point
├── docs                  # Ignore this folder. It is generated by `deno task doc`
├── src/types.ts          # Shared types
├── src/lti-handlers      # Hono LTI launch handlers
├── src/routes/           # Provided app route handlers
├── src/scoring/          # Provides the Dialang scoring algorithms
├── src/storage/          # A class based API which uses Deno KV for persistence
├── src/templates/        # HTMl templates, rendered in the routes
├── src/utils/            # Some utility methods
├── deno.json             # Deno config, tasks, and import map
└── deno.lock             # Lockfile
```

## Conventions

- Use Deno's built-in tooling (`deno fmt`, `deno lint`) rather than adding Prettier/ESLint.
- Prefer `npm:` or `jsr:` specifiers over a `node_modules`-based setup; keep imports mapped in `deno.json`.
- Use Hono's built-in validators (e.g. `@hono/zod-validator`) for request validation rather than hand-rolled checks.
- Group routes with `Hono` sub-app instances (`app.route('/users', usersRoute)`) instead of one giant file.
- Add any Deno KV access to `src/storage/denokv-storage.ts`. Don't sprinkle Deno KV calls throughout the codebase.
- Use explicit types for request/response shapes; avoid `any`.

## Testing

- Use `deno task test` for unit tests
- Use `deno task e2e` for end to end Playwright tests
- Unit test files live alongside source as `*_test.ts`.
- Prefer Hono's `app.request()` for testing routes without spinning up a real server.

## Notes for Agents

- This project does not use Node.js or npm as the primary runtime — don't suggest `npm install`,
`package.json` scripts, or Node-specific APIs (`fs`, `path` from `node:` without the specifier)
unless explicitly needed via `npm:` compat.
- Always check `deno.json` for existing tasks and import aliases before adding new dependencies.
- Prefer standard library modules from `jsr:@std/*` where applicable.
- Never scan anything under static/content unless I specifically ask you to. That directory contains
statically generated content and is not part of the codebase.
